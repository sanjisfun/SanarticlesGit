What is GitHub

GitHub is a cloud platform for hosting git repositories, collaborating via pull requests, tracking work with issues and projects, and automating CI/CD using Actions. Suitable for personal projects, teams, and enterprises.

Key features

  • Repositories: code, history and versions.
  • Branching & Pull Requests: code review and discussion.
  • Issues & Projects: planning and tracking work.
  • Actions: CI/CD automation and deployment.
  • Security: Dependabot, secret and code scanning.
  • Pages & Wiki: documentation hosting and static sites.

How to upload files — options and comparison

MethodWhen to useSteps (summary)
Web UI Small edits, README, single files Repo → Add file → Upload files → Commit
Git (local) Full development, history, branches git init/clone → add/commit → remote add → push
GitHub CLI (gh) Terminal workflows, PRs/issues from CLI gh auth login → gh repo create → git push
Git LFS Large binaries (>100MB) git lfs install → git lfs track → add/commit → push

Detailed steps

Via web

  1. Create a repository: GitHub → New repository → name + visibility + init README (optional).
  2. Upload files: Add file → Upload files → drag & drop or select → Commit.

Via Git (recommended)

# initialize and first commit
git init
git add .
git commit -m "Initial commit"

# add remote and push
git remote add origin https://github.com/USERNAME/REPO.git
git branch -M main
git push -u origin main

GitHub CLI

gh auth login
gh repo create my-repo --public --source=. --push

Git LFS (if needed)

git lfs install
git lfs track "*.bin"
git add .gitattributes
git add bigfile.bin
git commit -m "Add large file"
git push

Example workflow and example GitHub Actions workflow

Simplified Git flow

  1. main: stable branch, releases.
  2. feature/*: work on features.
  3. PR: open a pull request → review → CI → merge.
  4. Release: tag and deploy from main.

Example .github/workflows/ci.yml

name: CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '18'
      - run: npm ci
      - run: npm test
        env:
          CI: true

Best practices

  • Small commits: make clear, atomic changes.
  • Readable messages: describe why, not just what.
  • .gitignore: exclude build artifacts and secrets.
  • Secrets: use GitHub Secrets for CI.
  • Automated tests: run tests in Actions on every PR.

Security

  • 2FA: enable two-factor authentication.
  • Dependabot: automatic dependency updates.
  • Code scanning: static analysis and secret scanning.
  • Branch protection: protected branches and required reviews.
